# pdf-to-csv-extractor

Extract fields from text-based PDFs (invoices, statements, reports) into a clean CSV — and get a **validation report** that lists the values your rules found missing, in an unexpected format or inconsistent, instead of silently guessing.

```
samples/*.pdf  ──►  output.csv               (one row per PDF, Excel-ready)
                └►  validation_report.csv    (what needs a human look, and why)
```

## Quick start

```bash
pip install -r requirements.txt
python -m pdf2csv samples --config fields.example.yaml
```

```
5 file(s) -> output.csv
2 issue(s) -> validation_report.csv
```

## How it works

1. **Read** the text of each PDF (`pypdf`).
2. **Extract** each field with a rule from a YAML file — no code changes for a new document layout.
3. **Normalize** dates to ISO 8601 (`2026-11-02`, `03/11/2026`, `Nov 5, 2026` → `2026-11-xx`) and amounts to plain decimals (`USD 1,280.00` → `1280.00`). Ambiguous formats such as `1.280,00` or `11.009` are reported as `unparsable`, never changed silently.
4. **Validate**: required fields must be present and parse; cross-field checks (e.g. `subtotal + tax = total`) must hold.
5. **Write** the CSV (UTF-8 with BOM, so Excel opens it cleanly) and the validation report. A file that can't be read is reported as `unreadable` and the other files still run.

The report is only as good as the rules: it catches what the field rules and checks describe, so a real project starts by agreeing those rules on your sample documents.

## Field rules

```yaml
fields:
  - name: invoice_date
    pattern: 'Invoice Date:[ \t]*(\S.*)$'   # value = capture group 1; [ \t]* so an empty field can't borrow the next line
    type: date                          # text | date | money | int
    required: true                      # default
checks:
  - sum: [subtotal, tax]
    equals: total
```

Note: `03/11/2026` is read as day/month/year. Change `DATE_FORMATS` in `pdf2csv/extract.py` for month-first documents.

## Scope

- Works on **text-based** PDFs (the text can be selected in a PDF viewer).
- Scanned images (OCR), handwriting and complex multi-page line-item tables need a different approach.
- All sample documents are fictional and generated by `tools/make_samples.py`.
